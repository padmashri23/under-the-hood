The Memory Layer: Why Your AI Agent Forgets and How to Fix It

AI models forget everything between chats. Here's how to give your agent a memory, and keep it safe.

Researched & written November 2026 · ~9 min read · Sources cited throughout

🧠 Why agents need memory

Tell a support chatbot about a double charge on Monday. Come back on Tuesday and ask about the refund. It asks for your order number again. The bot isn't careless. It never knew you.

Every call starts from zero

An AI agent is a large language model (LLM) that uses tools to finish a task. ChatGPT and Claude are built on LLMs. The LLM itself is stateless. That means it keeps nothing from one request to the next. OpenAI's docs say it plainly: "each text generation request is independent and stateless."

So how does a chatbot remember your last message? The earlier messages are sent back to the model with every new request. Close the chat, and that history is gone.

What breaks without memory

  • The agent asks the same questions every time.
  • Work on a long task is lost when the chat ends.
  • Every user gets the same answers.

Short-term vs long-term memory

  • Short-term memory is the context window: all the text the model can read in one request. Think of it as the model's desk. It's small, and it's cleared after each chat.
  • Long-term memory is a separate store, like a database, that keeps facts between chats. Think of it as a filing cabinet next to the desk.

Memory is not the same as state

  • State is the agent's to-do note for the current task: which step it's on, and what its last tool returned.
  • Memory is what's worth keeping after the task ends.

📖 Words you'll see in this article

🗂️ The four types of memory

In plain words: Researchers sort agent memory into four kinds, borrowed from human memory. The 2023 CoALA paper uses all four, and LangChain's docs use three.

  • Working memory: what the agent is using right now. In practice, that's the context window.
  • Episodic memory: past events. Example: "Last month, this customer was charged twice and got a refund."
  • Semantic memory: facts. Example: the customer is on the Pro plan and prefers email.
  • Procedural memory: how to do things. Example: "Always check the order number before a refund." It lives in the system prompt, the agent's code and the model itself.

💡 Good to know: Some agents can update their own procedural memory. They rewrite their own instructions based on feedback.

📚 Knowledge vs memory

In plain words: Both end up in the context window, but they're different things.

  • Knowledge is shared. Your team writes and checks it: help articles, policies, product guides.
  • Memory is personal. The agent writes it as it works: this customer's plan, what they asked last week.

RAG: how knowledge gets in

RAG stands for retrieval-augmented generation. It's like an open-book exam: the agent looks up the right pages before it answers. The name comes from a 2020 research paper. It works in three steps:

  1. Chunking: cut each document into short passages.
  2. Embedding: turn each passage into a list of numbers that captures its meaning. Passages with similar meanings get similar numbers.
  3. Retrieval: when a question comes in, find the closest passages and add them to the prompt.

Why they need different rules

  • Knowledge changes only when your team edits a document.
  • Memory changes in every chat. It belongs to one person, and it needs an expiry date and a delete button.

💡 Good to know: Keep them apart. Otherwise, one customer's details can show up in another customer's answer.

🪟 Managing the context window

In plain words: The context window fills up as a chat goes on. A bigger window doesn't fully solve this. Anthropic's engineers describe "context rot": the more text in the window, the worse the model gets at recalling it. Three habits help:

  • Summarise old messages. When the window is nearly full, swap the old chat for a short summary. Anthropic calls this compaction.
  • Clear old tool results. If the agent read a file 40 steps ago, it can read it again when needed. Anthropic calls this "one of the safest lightest touch forms of compaction."
  • Save key facts to long-term memory. Then load back only the facts the current task needs.

What Anthropic measured

In September 2025, Anthropic released two features for Claude:

  • Context editing clears old tool results automatically.
  • The memory tool lets Claude save files outside the context window.

Anthropic tested them on its own internal search tasks. Anthropic doesn't describe its baseline in detail.

  • Context editing alone improved performance by 29%.
  • Context editing plus the memory tool improved it by 39%.
  • In a 100-turn web search test, context editing cut token use by 84%. It also let agents finish tasks that would otherwise fail.

💡 Good to know: These are a company's tests of its own product. Treat them as a guide, not a promise.

🧰 Memory frameworks: Mem0 and LangMem

In plain words: You don't have to build memory from scratch. Two popular options are Mem0 and LangChain's tools.

Mem0: a memory layer you plug in

  • You send Mem0 a conversation. It uses an AI model that "pulls out key facts, decisions, or preferences to remember."
  • Later, it finds the most relevant ones.
  • Each memory gets labels, such as a user_id, so every user's memories stay separate.
  • You can use Mem0's hosted service, or run its free, public code yourself.

LangChain: memory built into the framework

  • LangGraph is LangChain's framework for building agents. Memory is part of it.
  • Checkpointers save each chat, for example to your own Postgres or SQLite database.
  • Stores hold long-term memories that any chat can read.
  • LangMem adds tools to pull facts out of chats, keep user profiles, and let the agent improve its own instructions. That last one is procedural memory.

Other memory tools exist too, such as Letta and Zep. The same questions apply.

How to choose

  • What do you already use? If you build with LangGraph, its memory is already there.
  • Where must your data live? Both can run on your own servers.
  • What is the memory about? See Figure 6.

💡 Good to know: Don't choose by benchmarks, the standard tests used to compare tools. Mem0's own 2025 paper reports a 26% relative improvement over OpenAI on one. But that's a company testing itself.

🎯 Choosing the right memory for your agent

In plain words: What your agent does decides what it needs to remember. Take a customer support agent.

  • Episodic memory: past tickets and chats.
  • Semantic memory: the customer's details, plan and preferences.
  • Knowledge: RAG over your help articles and refund policy.
  • Best fit: Mem0. The memory is mostly about the customer, and it must carry over between chats.

💡 Rule of thumb: Pick Mem0 when the memory is about the user. Pick LangChain when it's about the work. Many systems use both.

🔄 The memory lifecycle

In plain words: Good memory is picky about what it saves. It also forgets on purpose.

  • What to save: stable facts, decisions, corrections and outcomes.
  • What to skip: small talk, one-off details and guesses. "The customer seemed annoyed" is a guess, not a fact.
  • Note the source and date. Who said it, and when? Figure 7 shows an example.
  • When facts clash, the newer confirmed fact wins. Say the customer said "Basic plan" in March, but billing shows Pro since June. Pro wins. Mem0's newer version keeps old facts as history but ranks current ones higher.
  • Forget on purpose. Mem0 lets you set an expiry date on each memory. Anthropic's docs suggest you "periodically delete memory files that haven't been accessed in a long time." If a user asks you to delete their data, do it.

💡 Good to know: Some systems use several agents that work together. Give each one private memory plus shared memory, and decide who can write what. A billing agent might write payment facts that a chat agent can only read.

🔒 Privacy, security and common mistakes

In plain words: Memory holds personal data. Treat it with care.

  • Don't save sensitive data you don't need. Anthropic advises you to "add validation that strips sensitive data before your handler writes the file." In other words, check and clean the data before saving it.
  • Keep users and companies strictly apart. Filter every save and every lookup by user and company. Anthropic's Claude app keeps a separate memory for each project.
  • Let users see, fix and delete what's saved. Claude's app lets users view and edit a memory summary.
  • Watch for memory poisoning. Say an agent reads a web page with hidden instructions and saves them as a "fact". Now the attack lasts beyond that one chat.

💡 Good to know: OWASP, a well-known security group, lists memory poisoning as ASI06 in its Top 10 for Agentic Applications. Only save facts from trusted sources, and record where each one came from.

📋 Memory at a glance

  • Are your documents (knowledge) kept apart from user facts (memory)?
  • Do memories expire, and can users delete them?
  • Is every save and lookup limited to one user and one company?
  • Is text from web pages and emails checked before it becomes a memory?

Where to start

  1. Pick the one fact users repeat most, like their plan.
  2. Save it with a source, a date and a user ID.
  3. Load it at the start of each new chat.
  4. Add summarising once chats get long.
  5. Add expiry dates and a delete option.

✅ Conclusion

An AI agent that forgets isn't broken. That's how language models work. Memory is the code you add around it. Get one fact right, then see if the complaints stop.
